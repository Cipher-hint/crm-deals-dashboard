# Дашборд сделок CRM — описание для проверяющего

## Назначение и сценарии

Приложение встраивается в портал Битрикс24 как пункт левого меню и показывает аналитику по сделкам CRM. Данные читаются через API Вайбкод от лица владельца личного ключа: все пользователи, которым доступна страница, видят одну и ту же выборку. Отдельный вход в приложение не делается.

Реализованные сценарии:

1. **Сводка по стадиям.** Для сделок, созданных в выбранном периоде, считается количество и сумма в разрезе `stageId`. Название стадии и цвет берутся из справочника статусов CRM, воронка — из категорий сделок.
2. **Ключевые показатели.** Сумма и число открытых сделок (`closed = false`), число и сумма выигранных (`stageSemanticId = S`), средний чек (сумма выигранных / их число; если выигранных нет — средняя сумма всех сделок периода).
3. **Последние сделки.** До 20 записей, отсортированных по дате создания: название, сумма, стадия, ответственный.
4. **Фильтр периода.** Пресеты 7 / 30 / 90 дней и «все время», плюс произвольный диапазон дат создания. Неполная пара дат, перепутанные границы и несуществующая дата отклоняются с понятным сообщением.

## Скоупы

| Скоуп | Зачем |
| --- | --- |
| `crm` | Чтение сделок, агрегатов, стадий (`statuses`) и воронок (`deal-categories`). Без него дашборд не из чего собрать. |
| `user` | Имена ответственных и текущего владельца ключа (`/v1/users`, `/v1/users/me`). |
| `placement` | Публикация в интерфейс портала, место встраивания `LEFT_MENU`. Без него приложение не появится в левом меню. |

Платформенные скоупы `vibe:infra` / `vibe:storage` используются только при создании сервера и выкладке, в запросах дашборда к CRM их нет.

## Известные ограничения

- Выборка ограничена правами владельца личного API-ключа. Это не персональная воронка каждого сотрудника портала.
- Фильтр действует по дате **создания** сделки, а не по дате перехода в «успех». Выигранные за период — это сделки, созданные в периоде и сейчас находящиеся в семантике `S`.
- Агрегаты суммы на очень больших выборках у Вайбкод могут быть усечены (лимит 5000 записей). На текущем портале объём меньше, усечение не срабатывает.
- На портале несколько воронок (квалификация, лицензия, продление, услуги). Сводка показывает стадии всех воронок одним списком, с подписью воронки.
- Открыть приложение по прямой ссылке `app-….vibecode.bitrix24.tech` может владелец ключа (политика доступа сервера по умолчанию `OWNER_ONLY`). Внутри Битрикс24 страница открывается через место встраивания `LEFT_MENU`.

## Инструкция для проверяющего

1. Откройте живое приложение: https://app-bfeac934a09d.vibecode.bitrix24.tech  
   (вход через Bitrix24, сервер в режиме Black Hole).
2. На портале `safekit.bitrix24.ru` в левом меню должен появиться пункт **Дашборд сделок**. Если пункта нет сразу — откройте каталог приложений портала и карточку **Дашборд сделок CRM**.
3. Убедитесь, что видны три KPI, таблица стадий и список сделок.
4. Переключите пресет на «7 дней», затем «Все время»: набор стадий и список должны измениться. Неполную пару дат или перепутанные границы система отклоняет сообщением, а не пустым экраном без объяснения.
5. Исходный код — в этом репозитории / архиве, без API-ключей. Ключ передаётся только переменной окружения `VIBE_API_KEY` на сервере.
