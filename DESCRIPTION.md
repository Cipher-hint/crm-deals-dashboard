# Дашборд сделок CRM — описание для проверяющего

## Назначение и сценарии

Приложение встраивается в портал Битрикс24 как пункт левого меню и показывает аналитику по сделкам CRM **от лица текущего сотрудника**. Сессию подставляет шлюз Вайбкод (`X-Vibe-Authorization`). Сервер вызывает API с `X-Api-Key: vibe_app_…` и `Authorization: Bearer <сессия>`. Без сессии `/api/dashboard` отвечает 401 и **не** откатывается на личный `vibe_api_`. Личный ключ в окружении рантайма отсутствует. Оформление — корпоративный стиль SafeKit. Вкладка «Помощь» содержит инструкцию и блок для ИТ/ИБ.

Реализованные сценарии:

1. **Сводка по стадиям.** Для сделок, созданных в выбранном периоде, считается количество и сумма в разрезе `stageId` и валюты. Название стадии и цвет — из справочника статусов CRM. Если агрегат усечён (лимит выборки API), на экране показывается предупреждение.
2. **Ключевые показатели.** Сумма и число открытых сделок (`closed = false`), число и сумма выигранных (`stageSemanticId = S`), средний чек. Суммы форматируются по валюте сделки, не фиксированным RUB.
3. **Последние сделки.** До 20 записей по дате создания: название, сумма в валюте сделки, стадия, ответственный. Имена ответственных запрашиваются по их `id`, а не полным справочником пользователей.
4. **Фильтр периода.** Пресеты 7 / 30 / 90 дней и «все время», плюс произвольный диапазон дат создания. Неполная пара дат, перепутанные границы и несуществующая дата отклоняются с понятным сообщением.

## Скоупы

| Скоуп | Зачем |
| --- | --- |
| `crm` | Чтение сделок, агрегатов, стадий (`statuses`) и воронок (`deal-categories`). Без него дашборд не из чего собрать. |
| `user` | Имя текущего сотрудника (`/v1/users/me`) и имена ответственных по `id`. |
| `placement` | Публикация в интерфейс портала, место встраивания `LEFT_MENU`. Без него приложение не появится в левом меню. |

Платформенные скоупы `vibe:infra` / `vibe:storage` в рантайме приложения не используются. Деплой выполняется отдельно личным ключом разработчика, в контейнер он не передаётся.

## Рантайм-ключ (`GET /v1/me`, без секрета)

Ключ приложения создан в режиме `READONLY`. Вызов `GET /v1/me` ключом `vibe_app_` (без сессии, ключ в ответ не включён):

```json
{
  "type": "oauth_app",
  "scopes": ["crm", "user", "placement"],
  "accessMode": "READONLY"
}
```

Точные поля снимаются живым `GET /v1/me` ключом приложения (без сессии); секрет ключа в этот блок не входит.

## Известные ограничения

- Выборка ограничена правами **текущего** сотрудника портала, а не владельца сервера.
- Фильтр действует по дате **создания** сделки, а не по дате перехода в «успех». Выигранные за период — это сделки, созданные в периоде и сейчас находящиеся в семантике `S`.
- Агрегаты суммы на выборках больше лимита API усекаются; дашборд показывает это явно, а не молча занижает цифру.
- На портале несколько воронок. Сводка показывает стадии всех воронок одним списком, с подписью воронки.
- Прямой заход на `app-….vibecode.bitrix24.tech` без сессии шлюза не читает CRM (401). Рабочий путь — пункт **Дашборд сделок** в левом меню.
- Справочники и список сделок читаются через `POST /v1/batch`. Агрегаты остаются отдельными вызовами (`aggregate` в пакет не входит). При HTTP 429 сервер ждёт `Retry-After`; 401 и 403 не повторяет.

## Инструкция для проверяющего

1. Откройте приложение **из левого меню** портала `safekit.bitrix24.ru` — пункт **Дашборд сделок**. Прямая ссылка без сессии должна дать 401 на `/api/dashboard`.
2. Убедитесь, что видны три KPI, таблица стадий и список сделок, в подзаголовке — имя текущего пользователя.
3. Переключите пресет на «7 дней», затем «Все время». Неполную пару дат система отклоняет сообщением.
4. Исходный код: https://github.com/Cipher-hint/crm-deals-dashboard — без API-ключей. В рантайме только `VIBE_APP_KEY`.
